Running locally

Getting the web client running against a Supabase project.

Requirements

ToolNotes
Node.js 20+Next.js 16 requires a modern runtime.
pnpmThe repo ships a pnpm-lock.yaml; other package managers will drift.
Supabase projectPostgres, Auth, Realtime and Storage.
Xcode 16+iOS client only.

Install

git clone https://github.com/polardev-ui/disband-latest.git
cd disband-latest
pnpm install

Environment

Create .env.local. The app reads these at boot, so restart the dev server after editing.

# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
SUPABASE_SERVICE_ROLE_KEY=<service role key>   # server-side only

# Stripe (billing)
STRIPE_SECRET_KEY=sk_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_...
STRIPE_BASIC_PRICE_ID=price_...
STRIPE_SUPER_PRICE_ID=price_...
STRIPE_WEBHOOK_SECRET=whsec_...

NEXT_PUBLIC_APP_URL=http://localhost:3000

Never expose the service role key to the browser. It bypasses Row Level Security entirely. It must only appear in server-side code, and must never be prefixed NEXT_PUBLIC_.

A common setup mistake is putting a sk_live_… secret key in STRIPE_BASIC_PRICE_ID. Price IDs always start with price_; checkout fails with an opaque error otherwise.

Database

Migrations live in supabase/migrations/ and are applied in filename order. They are written to be idempotent (if not exists, create or replace), but check what a migration does before running it against data you care about.

supabase db push

Run

pnpm dev        # http://localhost:3000
pnpm build      # production build
pnpm lint

iOS client

The Xcode project is generated from project.yml by XcodeGen and is not checked in. Regenerate it whenever files are added or removed, or Xcode will not see them:

cd ios
xcodegen generate
open DisbandiOS.xcodeproj

Forgetting xcodegen generate after adding a Swift file produces confusing cannot find <Type> in scope errors for code that plainly exists on disk.
