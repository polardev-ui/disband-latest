Architecture

Three clients, one backend, and very little bespoke server code.

Shape of the system

  Web (Next.js)     Desktop (Tauri)      iOS (SwiftUI)
        |                  |                    |
        +--------- Supabase client SDKs --------+
                           |
        Postgres  +  Auth  +  Realtime  +  Storage
                           |
        Next.js route handlers (Stripe, moderation,
        link previews, status) using the service role

Most reads and writes go straight from the client to Postgres through the Supabase SDK, with Row Level Security deciding what is allowed. Server-side route handlers exist only where something must not be trusted to the client — verifying a Stripe webhook signature, or acting with elevated privileges.

Because clients talk to the database directly, Row Level Security is the security model. Any rule enforced only in React or Swift is a convenience, not a control. See Security & RLS.

Web client

PathContains
src/app/App Router pages and API route handlers.
src/components/discord/The main chat surface — channel list, chat canvas, composer, modals.
src/contexts/AppContext.tsxCentral store: session, servers, channels, messages, friends, notes, realtime subscriptions.
src/hooks/Calls (useCallManager), subscriptions, media devices.
src/lib/Supabase clients, WebRTC helpers, theming, subscription entitlements.
supabase/migrations/Schema, RLS policies and RPCs, applied in filename order.

Desktop

Tauri wraps a static export of the web app. Two consequences worth knowing:

  • The origin is tauri://localhost, so anything deriving a URL from window.location needs a fallback to the configured web app URL.
  • Every external host the app talks to must be present in the CSP connect-src.

iOS

A native SwiftUI app using supabase-swift and the same tables. It is not a web view. Themes are stored on the shared profiles.theme column, so a theme chosen on the phone applies on the web too.

Calls

Calls are peer-to-peer WebRTC. Supabase Realtime carries only signalling — ring, accept, reject, cancel, offer, answer, ice, leave — and media never passes through the server. See Realtime for the channel layout.
