HTTP endpoints

These are internal application routes, not a public API.

Every route below exists to serve Disband's own clients. They are authenticated by session cookie, are not versioned, and may change without notice. There is no API token scheme — see Building a bot.

Billing

RouteMethodPurpose
/api/stripe/create-checkoutPOSTCreates an embedded Checkout session for basic or super. Promotion codes enabled.
/api/stripe/portalGETReturns a Stripe billing portal URL.
/api/stripe/syncPOSTReconciles the caller's subscription directly from Stripe.
/api/stripe/webhookPOSTStripe events. Verifies the signature against STRIPE_WEBHOOK_SECRET.

/api/stripe/sync exists because a webhook is a single point of failure. If its URL or signing secret is wrong, a customer is charged and the app never learns about it. Reconciling on demand means a purchase applies even when the webhook never fires.

Reading data

There is deliberately no REST layer over the tables. Clients query Postgres through the Supabase SDK, and RLS decides what comes back:

const { data, error } = await supabase
  .from("messages")
  .select("*, author:profiles(*)")
  .eq("channel_id", channelId)
  .order("created_at", { ascending: false })
  .limit(50);
