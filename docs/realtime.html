Realtime

Two mechanisms: Postgres change streams for data, and ephemeral broadcasts for signalling.

Postgres changes

Tables published to Realtime stream inserts, updates and deletes to subscribed clients. RLS applies, so a client only receives rows it is allowed to read.

const channel = supabase
  .channel(`messages:${channelId}`)
  .on("postgres_changes", {
    event: "INSERT",
    schema: "public",
    table: "messages",
    filter: `channel_id=eq.${channelId}`,
  }, ({ new: message }) => append(message))
  .subscribe();

Broadcast channels

TopicCarries
call-user:<userId>Inbound call signalling for one user: ring, accept, reject, cancel, leave.
call:<callId>Negotiation between two peers already in a call: offer, answer, ice.
typing:<scope>Typing indicators.

The call id is derived deterministically from both user ids sorted and joined, so each side computes the same value without a round trip.

Two traps worth knowing

Acknowledge broadcasts before unsubscribing. A send resolves as soon as the frame reaches the socket. If you unsubscribe immediately afterwards, the channel can be torn down before the server accepts the message, and it is silently dropped. Enable ack and wait for "ok".

const channel = supabase.channel(topic, {
  config: { broadcast: { self: false, ack: true } },
});
await subscribeChannel(channel);
const status = await channel.send({ type: "broadcast", event, payload });
if (status !== "ok") throw new Error("broadcast not acknowledged");
await channel.unsubscribe();

On iOS, retain the subscription token. onBroadcast returns a RealtimeSubscription that cancels the callback when it deallocates. Discarding it leaves the channel subscribed but with no listener — everything looks healthy and no message ever arrives.

// Store this; do not discard it.
self.listenSubscription = channel.onBroadcast(event: "call") { json in
    handle(json)
}
try await channel.subscribeWithError()
